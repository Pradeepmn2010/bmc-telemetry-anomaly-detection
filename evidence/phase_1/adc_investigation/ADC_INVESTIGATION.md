# ADC Investigation — AST2600 OpenBMC

## Experiment information

- Date: 1 November 2026
- Platform: AST2600 QEMU emulation
- OpenBMC firmware: v11.04
- ADC process: adcsensor (PID 449 during experiment)
- D-Bus unique name: :1.48
- hwmon device: iio_hwmon (hwmon18)
- Entity Manager configuration:
  - ADC0_12V: Index 0, ScaleFactor 0.1515
  - ADC8_12V: Index 8, ScaleFactor 0.1515

## Objective

Investigate the relationship between Linux IIO/hwmon voltage readings
and OpenBMC ADC sensor values published through D-Bus.

## Preliminary analysis

Both hwmon inputs and D-Bus voltage values increase across the
five samples.

The upstream dbus-sensors conversion reference is:

V = hwmon_millivolts / (1000 * ScaleFactor)

For ScaleFactor = 0.1515, the divisor is 151.5.

This formula is based on an upstream source revision. The exact
source revision corresponding to this firmware has not yet been
verified.

Measurements are sequential rather than simultaneous. The emulated
ADC signal changes rapidly, so differences between the calculated
and observed values must not be interpreted as a confirmed fixed
conversion offset.

## Preliminary findings

1. ADC0 and ADC8 show similar voltage trends.
2. in1_input and in9_input are candidate hwmon inputs for ADC0_12V
   and ADC8_12V respectively.
3. The device tree maps ADC0 channels to the first eight iio-hwmon
   inputs and ADC1 channels to the next eight.
4. Exact Entity Manager index-to-hwmon filename mapping still needs
   source-code or controlled measurement confirmation.
5. D-Bus calls through unique name :1.48 succeeded during this
   experiment, while calls through the well-known name failed.
6. The unique D-Bus name is transient and must be rediscovered
   for future experiments.

## Limitations

- Only five samples were captured.
- hwmon and D-Bus reads were sequential.
- ADC values are generated by an emulator, not physical hardware.
- Exact firmware source revision is not confirmed.
- No definitive channel mapping or conversion validation is claimed.
